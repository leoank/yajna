`readdir`, a stat only for symlinks, and the sort key lower-cased once per entry. Output
in `notes/runs/RUN-20261023-pjazct/output-after.txt`; the table is on the baseline's
page.

- 100 000 entries: 329 ms to the first page, against 1 300 before and a prediction of
  under 300. Close enough for the tree, which shows a spinner while it loads.
- 1 000 000 entries: 4.0 s, against 14.7 before and a prediction of under 3. The disk is
  most of it: Python's `os.scandir` alone took 3.5 s on the same directory (and `ls -f`
  7.7 s), so no listing that reads the whole directory can be much faster here.
- Memory rose from 99 to 192 MB with the cached sort keys, under the 300 MB predicted.
- A cached listing answers in about 1 ms, but a directory's cache is dropped when its
  mtime changes, so a million-entry directory a run is still writing into is read again
  after each new file.
